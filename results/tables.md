## Support sweep summary

Ranges go from the highest to the lowest completed support level. Times and memory are medians of 5 runs with `--unsorted` output to `/dev/null` (total = read + build + mine, where mining includes formatting the itemsets). Tree nodes / occurrences is the size of the initial FP-tree relative to the number of frequent-item occurrences inserted into it (lower = more prefix sharing). "Stopped at" is the first level that exceeded the budget.

## Runtime vs mlxtend

Medians of 3 runs. This implementation's time includes reading the .dat file, building the tree, mining and formatting every itemset; mlxtend's time is only the `fpgrowth()` call on an already one-hot-encoded DataFrame. All 13 settings produce identical itemsets (`tests/compare_mlxtend.py`). This implementation is single-threaded; mlxtend averaged ~1.25 CPU-seconds per wall-second, and forcing single-threaded BLAS (`OMP_NUM_THREADS=1` etc.) gave similar times, so the gap is not a threading effect.
